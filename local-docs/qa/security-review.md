# Security Review — RydeePortalWebsite

**Reviewer:** QA-SecReview (delegated by SWE Team Lead)
**Date:** 2026-08-06
**Scope:** Code-level security review of the SPA. Read-only, no code changes.
**Out of scope:** Backend service (`localhost:3000` / API Gateway), hosting, network, `npm audit` (already done; react-router RSC CSRF assessed N/A — library mode, no RSC).
**Threat model context:** Internal-ish admin/operator/rider portal; external WIP backend enforces authz and sets cookies (`credentials: 'include'`); MSW is dev-only per H6/main.tsx DEV-guard; sessions live in `localStorage` (accepted trade-off pending backend tokens — H7).

## Summary

- **Total findings:** 10
- **Critical:** 0 · **High:** 1 · **Medium:** 3 · **Low:** 4 · **Info:** 2

**Top three to act on:**
1. **S-01 (High)** — CSV export has no formula-injection guard; rider `name`/`area`/`cnic` flow untouched into cells starting with `=/+/-/@/\t`. Fix in this repo.
2. **S-02 (Medium)** — `AuthProvider.logout()` clears only client state; no `POST /logout` call, so backend session cookie remains valid until server-side TTL. Backend/repo joint fix.
3. **S-03 (Medium)** — `i18next` init sets `interpolation.escapeValue: false`. Currently safe (React auto-escapes JSX children) but the guard is fragile: any future `dangerouslySetInnerHTML={{__html: t(...)}}` or attribute sink (`href={t(...)}`, inline `style`) becomes an XSS sink. Add a lint rule or reverse the setting.

## Checks Performed (Negative — no finding)

- **XSS sinks (`dangerouslySetInnerHTML`, `innerHTML`, `document.write`):** Only `src/main.tsx` env-check screen uses `.innerHTML` with hard-coded static strings (no user/URL input). No `dangerouslySetInnerHTML` anywhere in `src/features/**` or `src/components/**`.
- **Leaflet popups (`ActiveRiders.tsx`):** Popup content rendered through JSX (`<Popup><div>{rider.name}</div></Popup>`), React auto-escapes. Data currently from local mock; when swapped to backend feed, the same JSX escaping continues to protect.
- **`ProtectedRoute` / `PublicOnly` guards:** Role compare is case-insensitive, unknown roles fall through to `roleHome() === "/login"` and `PublicOnly` triggers logout via `useEffect` — matches H3/H8 F1 trace. Client-side role checks are **explicitly not** the security boundary; the backend enforces authz on every `credentials: include` call. Documented, correct.
- **`ROLES` widening (H2):** `Admin` is not in the creatable-role list (`src/types/profile.ts` `ROLES = ["Operator", "Customer", "Rider"]`); `RegisterPage` cannot request `Admin`. F2 tripwire intact.
- **Session envelope validation:** `isEnvelopeV1` rejects malformed / expired (24h TTL) blobs and calls `clearSession()` on every reject path — no rehydration loop, no stale-session survival past TTL.
- **`.env`:** Present locally, `.gitignore`d, not in `git ls-files`. `.env.example` contains no secrets — only public API base URLs and boolean flags.
- **Secrets grep:** No hard-coded `password`/`token`/`secret`/`api_key` literals in `src/` outside expected sites (login form state, i18n strings, MSW seed passwords which are dev-only).
- **Console logging:** Three `console.*` calls; none log passwords, tokens, or full profile objects. `Dashboard.tsx:105` logs an i18n label + the error object — acceptable; watch that `err` is not an `ApiError` with sensitive backend body in prod (see S-08).
- **Vite proxy (`vite.config.ts`):** Proxy config only initialised when `command === "serve"` (dev). `vite build` produces a bundle with no proxy code paths. `cookieDomainRewrite: "localhost"` is dev-only. Safe.
- **MSW in prod bundle:** `rg` for `msw`, `mockServiceWorker`, and MSW handler seed strings (`0300444444`, `Ayesha`, `handlers/auth`) against `dist/assets/index-*.js` returns **zero hits**. DEV-guard + dynamic import tree-shakes cleanly. (Related nit: S-05 and S-06.)
- **Fetch-shape drift (H1/H6):** All fetch calls go through `src/api/client.ts`; endpoint constants live in `src/api/*.ts`. No feature imports `fetch` directly. Contract-frozen paths (`/user-login`, `/register-user`, `/get-all-riders`, etc.) match ADR-0003.

## Suggested Regression Tests (for the Frontend/Backend fixes)

1. **S-01:** `tests/unit/lib/csv.test.ts` — assert every prefix (`=`, `+`, `-`, `@`, `\t`, `\r`) gets the `'` neutraliser AND correct quoting. Round-trip: parse output with a CSV parser, verify original string recoverable modulo the leading quote.
2. **S-02:** `tests/e2e/logout.spec.ts` — after logout, hit a protected endpoint via `fetch(..., { credentials: 'include' })` from the browser and assert 401.
3. **S-03:** unit test on i18n init asserting `interpolation.escapeValue === true`; ESLint rule blocking `dangerouslySetInnerHTML` in `src/**` (with an allowlist for `src/main.tsx` env screen).
4. **S-07:** unit tests on `readArea` / `readSearch` for `?area=<script>`, `?area=Clifton`, `?area=` — expect fallback to `"all"` and length cap respectively.
5. **S-08:** unit test that `LoginPage` renders a mapped i18n key (not raw `err.message`) when API returns 500 with body `"Traceback..."`.

## Sign-off

QA blocks release on **S-01** landing before the AllRiders CSV export feature is enabled for end-users. S-02 and S-03 are release-blockers for the first production launch (not for internal preview). S-04 and S-10 are documented risks, not blockers, until scope grows.
